# Contributing to Keel

Thanks for your interest. Keel is in early planning, so the most useful contributions right now are ideas and feedback on the docs in `docs/`.

## Ground rules

- Open an issue before a large change, so we can agree on the approach first.
- Keep personal data out of the repo. Use fictional names (Acme, Northwind) in examples, tests and screenshots.
- Configuration goes through environment variables (see `.env.example` once it exists), never hardcoded paths, hosts or tokens.
- Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:` ...).

## Writing style

Plain, short sentences. No em dashes: use a period, comma, colon or parentheses instead.
